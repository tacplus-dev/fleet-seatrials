The deploy and test pipeline is defined here (`ci/`, docs/deploy-pipeline.md): tools, checks, cert, images, generate, diff, apply, post-deploy checks. `apply` runs by itself on main once `diff` succeeds (seatrials isn't production), and it applies only the render whose digest `diff` recorded. `signin-secrets` and `test-idp` stay manual; `ci/pipeline_test.sh` checks this on the rendered pipeline (#34). It reads this private repository only through the keyless `tacplus-reader` GitHub App: each job mints a one-hour, read-only token through WIF and Cloud KMS, and no GitHub token is stored (#29). KMS is asked as the job itself, then, if it refuses that principal, as the service account `fleet-seatrials-reader@`; each refusal is logged with KMS's HTTP status and error (#30). The `test` stage is the functional end-to-end suite (`deploy/e2e.sh` on `deploy/e2e.yaml`, #17): every capability SeaBeam relies on, 24 named items, each PASS, FAIL or WAITING with the open issues it waits on, published as the job's JUnit report. The platform checks and the sign-in provider check run. The test-IdP sign-ins run once the job has the test IdP's seeds (#27). The RPC-level items (tenants, public RPCs, records, streams, redo, kernel restart, the event trace) wait on #14, #3, tacplus-dev/tacplus#258 and #265. A deployment's key material (`FLEET_CRYPTO_YAML`, `FLEET_CA_PEM`) is generated by the manual `init-secrets` job into the project's variables, with a per-deployment bot user's token (`FLEET_INIT_TOKEN`), and skipped when it exists (#17). crypto.yaml is stored gzipped and base64-encoded, split into `FLEET_CRYPTO_YAML`, `FLEET_CRYPTO_YAML_2`, ... of at most 10,000 characters each (GitLab's limit on a value; this topology's is about 10,000), which `ci_crypto` joins and decodes. The `security` job (#36, `ci/security.sh`) runs OSV-Scanner on the tree, `govulncheck -mode=binary` on the pinned binaries, gitleaks on the history and the tree, and Trivy on the CI image and on the images this repository deploys (the test IdP's Keycloak and haproxy, for arm64; #41, #27), with `security-exceptions.yaml` enforced; `images` and `generate` wait for it, and it also runs on GitHub on every push, pull request and nightly.
